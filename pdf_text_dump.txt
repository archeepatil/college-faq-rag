What is a Pinecone Vector Database? 
Pinecone is a popular vector database used in building LLM-powered applications. It is versatile and 
scalable for high-performance AI applications. It’s a fully managed, cloud-native vector database 
with no infrastructure hassles from users. 
LLM bases applications involve large amounts of unstructured data, which require sophisticated 
long-term memory to retrieve information with maximum accuracy. Generative AI applications rely 
on semantic search on vector embeddings to return suitable context based on user input. 
Pinecone is well suited for such applications and optimized to store and query many vectors with 
low latency to build user-friendly applications. Let’s learn how to create a pinecone vector database 
for our question-answering application.

Step 3: Split the Texts Data 
Text embeddings and LLMs perform better if each document has a fixed length. Thus, Splitting texts 
into equal lengths of chunks is necessary for any LLM use case. we will use 
‘RecursiveCharacterTextSplitter’ to convert documents into the same size as text documents. 
 
# split the docs using recursive text splitter 
def split_docs(documents, chunk_size=200, chunk_overlap=20): 
  text_splitter = RecursiveCharacterTextSplitter(chunk_size=chunk_size, 
chunk_overlap=chunk_overlap) 
  docs = text_splitter.split_documents(documents) 
  return docs

To build a Data Retrieval Agent using LangChain, you need to create a system that can understand a 
user's question, determine which data source or tool holds the answer, fetch that data, and 
synthesize a response. 
• The step-by-step architecture to build one using LangChain and LangGraph (the modern 
standard for stateful agents). 

=== PAGE 13 ===
 
Step 1: Define the LLM and Memory 
First, initialize the central reasoning engine (the LLM) and a memory saver to track the conversation 
history. 
• LLM Setup: Choose an execution model capable of reliable tool calling (e.g., GPT-4o, Claude 
3.5 Sonnet, or Llama 3.1). 
• Memory: Use MemorySaver to allow the agent to remember context across multi-turn 
dialogues. 
Step 2: Build and Register Data Retrieval Tools 
Tools are Python functions that your agent can execute to fetch external data. You must wrap 
them using the @tool decorator and provide clear docstrings so the LLM knows when and how to 
use them. 
• Vector Store / RAG Tool: For retrieving unstructured data (PDFs, internal wikis). 
• SQL Database Tool: For querying structured transactional or user data. 
• API / Web Search Tool: For pulling real-time data from external software or the internet. 
Step 3: Create the Agent State 
Define what information the agent needs to track as it runs.  
In LangGraph, this is typically a state object containing a list of messages.  
Every time the LLM speaks or a tool runs, new messages are appended to this state. 
Step 4: Construct the Agent Graph Nodes 
An agent workflow consists of two primary operational nodes: 
1. The Agent Node: Takes the current state (conversation history), passes it to the LLM, and 
asks the LLM whether it needs to call a tool or reply directly to the user. 
2. The Tool Execution Node: If the LLM decides to call a tool, this node intercepts the tool 
request, runs the Python function (e.g., executes an SQL query), and feeds the results back 
into the message history. 
Step 5: Define the Routing Logic & Edges 
• Link your nodes together with conditional logic: 
• If the LLM's response contains tool_calls, route the graph to the Tool Execution Node. 
• Once the tool finishes running, route back to the Agent Node so the LLM can read the 
retrieved data. 
• If the LLM decides it has enough information to answer the user, route to the End of 
the graph. 
Step 6: Compile and Execute 

=== PAGE 14 ===
Compile the graph workflow into a runnable application. When you invoke it with a user 
query, the agent will autonomously loop through steps 4 and 5 until it retrieves all necessary 
data to formulate its final answer. 
 
 
 Basic Code Architecture (Python) 
 
from langchain_openai import ChatOpenAI 
from langchain_core.tools import tool 
from langgraph.prebuilt import create_react_agent 
from langgraph.checkpoint.memory import MemorySaver 
 
# 1. Define Data Retrieval Tools 
@tool 
def query_company_database(customer_id: str) -> str: 
    """Queries the SQL database for active customer subscription statuses.""" 
    # Your database fetching logic goes here 
    return f"Customer {customer_id} is on the Premium Plan." 
 
tools = [query_company_database] 
 
# 2. Initialize the LLM with Tool Binding capabilities 
llm = ChatOpenAI(model="gpt-4o", temperature=0) 
 
# 3. Initialize Memory Checkpointer 
memory = MemorySaver() 
 
# 4. Compile the Agent Graph 
agent_executor = create_react_agent(llm, tools, checkpointer=memory) 
 
# 5. Run the Agent 
config = {"configurable": {"thread_id": "user_session_1"}}
